# アーキテクチャ（現状）

現在の実装は **フェーズ1（MVP）** です。バックエンドは最小限で、タイマーのすべてのロジックはブラウザ側で動作します。

---

## ディレクトリ構成（実装済み）

```text
1.pomodoro/
├── app.py                      # Flask アプリケーション本体
├── requirements.txt            # Python 依存ライブラリ
├── templates/
│   └── index.html              # Jinja2 テンプレート（単一ページ）
└── static/
    ├── css/
    │   └── style.css           # スタイルシート
    └── js/
        ├── timer-core.js       # タイマーコアロジック（純粋関数）
        ├── timer-core.test.js  # ユニットテスト（Node.js test runner）
        └── ui.js               # DOM 操作・イベントハンドリング
```

> `models/`・`repositories/`・`services/` はフェーズ2以降に追加予定であり、現時点では存在しません。

---

## レイヤ構成

```
┌─────────────────────────────────────────────┐
│  ブラウザ（フロントエンド）                   │
│  ┌──────────────┐   ┌──────────────────┐   │
│  │ timer-core.js │   │     ui.js        │   │
│  │ 状態遷移・計算│──▶│ DOM 更新・操作   │   │
│  │ （純粋関数）  │   │ LocalStorage 保存 │   │
│  └──────────────┘   └──────────────────┘   │
└─────────────────────────────────────────────┘
                ↕ HTTP
┌─────────────────────────────────────────────┐
│  Flask サーバー（バックエンド）               │
│  GET /  →  index.html をレンダリングして返す  │
└─────────────────────────────────────────────┘
```

---

## 設計方針

- **フロントエンド主導**: タイマーの進行・状態管理はすべてブラウザ側で完結する
- **Flask は薄く**: 現在はページ配信のみ。ビジネスロジックを持たない
- **純粋関数ベース**: `timer-core.js` の状態遷移は副作用を持たない純粋関数で実装されており、テストが容易
- **状態の不変性**: イベントを受け取って新しい状態オブジェクトを返す reducer パターンを採用
- **時刻計算方式**: 残り時間は `endsAt - Date.now()` で都度再計算する（タブ非アクティブ復帰後の時間ズレ対策）

---

## 設定の永続化

現フェーズでは、ユーザー設定はサーバー側のデータベースではなく **ブラウザの LocalStorage** に保存されます。

- ストレージキー: `pomodoro.settings.v1`
- 保存形式: JSON
- 読み込み: 起動時に自動取得。パース失敗時はデフォルト値を使用
